# Household lists and reference notes

Recipes requested for durable saving or retrieval belong in the Knowledge
skill. This store still owns older saved reference notes and supplies their
exact scoped content when they are explicitly filed as recipes.

Compose the authorized `household_lists_*` tools. The canonical list/note store
owns these records; do not create a second task database or edit its files.
Use natural conversation and preserve meaning, names, quantities, dates and
quoted wording. Do not require command punctuation or exact phrases.

Keep the requested item wording in `text` and the ISO date in `due`. Do not
append rendered due labels, list IDs, checkboxes or confidence metadata to the
item text; the owning store formats those fields. When reading an existing
record, treat its displayed due annotation as metadata, not part of a new title.

Capture things to buy as shopping, actions/errands as task, delegated matters as
waiting, and reference material as note. Use household scope for ordinary shared
shopping and shared-channel requests. Keep private personal requests in personal
scope; ask when a choice could disclose private information or materially change
the requested action. A shared channel never reads a private store as fallback.

Read state and stable IDs to resolve follow-ups. Complete, restore or remove the
intended record by ID. Similar text is not authority to change every match.
Removal is recoverable in Removed and needs no second confirmation for an authorized request. Completion, removal and restoration return their owning receipts.
Use search/recent notes to retrieve references and report actual committed
receipts. A list item's confidence label is not durable memory confirmation.

Events belong on the household calendar; stable preferences and learned facts
belong in the grounded memory wiki. A preparation task or deadline may accompany
an event if the request calls for it, but do not duplicate an appointment as a
list item merely to remember it. A reminder or future tool run uses schedule
capabilities with the appropriate authorization, not a note pretending to run.

For a dedicated household brain-dump prompt, Main decomposes clear calendar,
list, reminder and memory intentions, loads matching contexts and executes clear
authorized items. Ask concise linked questions only about uncertain details;
leave other clear work moving. Keep the native task/checkpoint and normal reply
context intact. Do not poll mail or consume an inbox automatically through this
skill. A schedule created disabled must be reported as disabled.

Use `household_lists_display` for a current read-only household projection,
then publish through an authorized display capability when requested. Kitchen
publication is shared only; do not include private notes, financial rows or
conversation history. A display is a projection, never a new editable authority.
