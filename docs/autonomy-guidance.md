# Optional guidance and independent execution

Household control 0.13.0 deployed and independently verified November 27, 2026. Candidate acceptance and protected activation are complete.

The current owner request authorizes implementing the autonomy audit except changes to Ollama serialization/model residency. Native execution/session/cancellation and existing credential custody remain the authorities. Guides describe useful methods; loading a guide, declaring outcomes, binding an ordinary clarification or publishing a prescribed progress layout must not authorize or block an otherwise authorized tool.

## Reuse decisions

| Responsibility | Decision | Authoritative owner |
| --- | --- | --- |
| Execution, sessions, optional children/goals and cancellation | Reuse native OpenClaw; adapt unnecessary admission limits, no second engine/queue | Existing native session/runtime |
| Current identity, source, audience and account permissions | Reuse | Existing native admission and protected credential service |
| Skills and coordination helpers | Adapt to optional guidance and convenience APIs; remove guide-digest prerequisites and mandatory ceremonies | Existing skill files and optional task helpers |
| Operation IDs, receipts and artifacts | Reuse automatic capture, immutable files and scoped attachment delivery | Existing domain owners and ArtifactStore |
| Gmail bodies, HTML and attachments | Adapt the existing connected Google read adapter under existing readonly consent | Existing credential service for provider access, ArtifactStore for returned files |
| Input, evidence and working context | Adapt arbitrary local ceilings; retain actual native context accounting, pagination and compaction | Existing transports and native context projection |
| Runtime/config changes | Adapt through separately pinned reproducible patches and existing protected promotion | Existing deployment owner; retain original V5/workshop patch identities |

No new task engine, registry, queue, memory database, credential store or configuration authority is introduced. Mutable implementation copies stay separate from immutable reference code. Current business records are never rolled back to undo a software attempt.

## Ownership and delivery

OAuth secrets stay in the existing protected vault/credential service. Only scoped provider results cross its existing consumer socket, with current account/source checks. Gmail's existing readonly permission permits content and attachment retrieval; sending and state mutation are outside that consent and are not enabled by this work.

The existing artifact owner stores returned files with their private owner/conversation/source scope. Readable projections and workspace copies name that authoritative source and do not become another mailbox or store of record. Ordinary receipts continue to capture actual effects automatically. Optional helper metadata describes work without granting authority or vetoing unrelated current authorized work.

The large existing runtime module is touched only to remove guide/ceremony coupling from its composition and authority checks. New content/attachment parsing belongs in focused provider modules rather than adding responsibilities to that module.

## Fixed decisions

Keep OLLAMA_NUM_PARALLEL=1, OLLAMA_MAX_LOADED_MODELS=1, native CDI, model volumes and serving topology unchanged. Preserve accepted Main 131072/high defaults and do not introduce an output/token-spending cap. Local model metadata's 2048 fallback is not treated as a generation cap. Native reasoning/model choices remain available through their existing optional mechanisms.

Do not activate additional accounts/grants, new OAuth scopes, held onboarding or scheduling. Preserve current secret separation and exact-source cancellation. API-required value types and provider-imposed capabilities remain real contracts; arbitrary guide/workflow restrictions are removed rather than replaced with larger fixed quotas.
