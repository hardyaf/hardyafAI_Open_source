## Built behavior and reuse

The build joins selected domain skills, native goal/child continuation, durable
questions and outcome evidence, private/shared wiki grounding, reasoning-led
Uplift primitives, isolated Python/output harvesting, diagnosis without repairs,
Android task/media/library views, protected Discord admission and a revocable
kitchen projection. Stock OpenClaw owns sessions, goals, subagents, scheduling
and transcripts. There is no parallel agent engine, task queue or memory store.

| Concern | Reuse/adaptation | Owner and lifecycle |
| --- | --- | --- |
| Delivery and controls | Adapt existing submission/control ledger | Exact request metadata, known versus unknown outcomes, waiting state, targeted stop/replay receipts and current authorization. |
| Consecutive task work | Reuse native goal/spawn/yield/wake | Existing checkpoint CAS and immutable handoffs/questions/outcome artifacts; no second goal ledger. |
| Invocation and loaded skills | Adapt existing execution-grant row | Exact source/run/session/root/goal/agent/mode; bounded one-use invocation and domain ID/digest projections, identity-change invalidation. Neither projection grants capability. |
| Questions/approval | Reuse task checkpoint and current human source | Freeform replies remain prompts; explicit approval requires the exact current question/resource/operation and signed decision. |
| Contacts/OCR | Reuse Rolodex/revision and local document owners | Every card/source is retained and reported; local extraction precedes the first field save. Later correction/redo needs an ordinary fresh response. |
| Memory | Adapt managed source/topic/journal and native wiki/index | Grounded facts versus candidates, provenance/correction/forgetting, exact personal/shared audience and resumable projections. |
| Receipts | Adapt Uplift financial authority | Candidate/review/acceptance revisions, evidence and reconciliation; private PDF/XLSX projections, no second financial ledger. |
| Analysis | Reuse actual native isolated child | Fixed no-network helper, current native/sandbox proof, immutable input/output manifests and owning verification. |
| Diagnosis | Adapt redacted evidence and report tools | Explicit sticky operator mode; observations/hypotheses and recommendations, no repair, secret retrieval, job replay or general shell. |
| Android/read views | Reuse signed device authority and owning queries | Current-resource read projections and scoped artifacts; no general HTTP tool executor. |
| Kitchen | Adapt the same device authority with display kind | Revocable household-only snapshot and explicit safe publication; no access back to private source/conversation APIs. |
| Credentials/scheduling | Reuse protected resolver/native scheduler | Real vault/provider setup and scheduled execution acceptance remain separate; ordinary jobs stay disabled. |

Application SQLite owns identities, submissions, control/effect receipts,
checkpoint pointers and execution/display references. ArtifactStore owns immutable
files. Native OpenClaw owns goals/runs/children/jobs/transcripts; Contacts owns
Rolodex sources/revisions; Uplift owns financial truth; managed wiki sources own
knowledge and native indexes are rebuildable projections. Read/display views
refresh from these owners and lose access when their source or grant is removed.
Publication revocation removes display access without changing its source file.

## Integration corrections established by the campaign

The measured native fixes cover atomic goal-start payload compatibility; removal
of a restart-unsafe global hook; gateway versus worker/discovery resource lifetime;
ordinary prompt projection; exact deferred invocation proof across native
registries; trusted original-goal continuation when public run projection lags;
phase-child assignment isolation; selected-contract loading/digests; actual native
progress/owning-outcome completion; current child/source/device/control fences;
and exact artifact HTTP content framing. These reuse existing owners rather than
introduce a self-prompt engine or accepting guessed/repaired tool arguments.

The latest integrity correction prevents a completed turn from becoming a
completed request when its source has no goal binding and the current native
goal is nonterminal. Maintenance/native-end handling reports
`native_goal_binding_missing`; it does not adopt an arbitrary goal from session
recency or a cleared public run ID. Receipt identity and newer terminal/binding
decisions are reread across awaits. The legacy abort path also needs fresh native
proof before calling an unbound source complete; otherwise it safely cancels.
Old completed-goal or no-goal ordinary follow-ups retain their legitimate path.
No-goal model goal creation itself remains an observed behavior defect.

Ordinary readiness now includes `tools.updatePlan=true` and `progress_card`
appended to the main/Natasha adult policies. Native plugin and control service
also use the same canonical domain file. The previous staged copy was semantically
identical to canonical policy, so no permission/content divergence was found;
the stale authority pointer itself was repaired. The existing preparer now accepts
an explicit active-domain path, and promotion verifies both consumers agree.
No other model, Google, Discord, credential, sandbox or identity policy changed. Native safeguards against replaying deterministic
effects remain intact. See [native boundaries/analysis](NATIVE-TASK-HOOKS-AND-ANALYSIS.md),
[task flow](TASK-FLOW-IMPLEMENTATION.md) and [model/runtime limits](model-runtime-known-issues.md).
