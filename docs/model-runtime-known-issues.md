## Native continuation boundary

The installed native finalizer refuses a revision rewind after potential deterministic effects. Preserve that safeguard. Unfinished-plan continuation is armed by the actual native progress tool's current-run callback; an external progress projection alone does not arm it. Do not add a self-prompt queue, forge a callback or hide effects from the classifier.

The clean Qwen parent/child yield/wakeup demonstrates one consecutive-prompt path. The affected clarification/restart and forced compaction cases now have recorded passes. Queued restart and broader recovery remain open. A durable question waits for a human; loaded contracts or plan metadata never grant authority or change an audience.

## Historical parser evidence and uncertainty

On the prior provider baseline, inspected logs showed two HTTP500 tool-argument parser failures with reasoning prose mixed into JSON. Other redacted errors did not retain enough detail to establish the same cause. Upstream [reasoning-argument](https://github.com/ollama/ollama/issues/12203) and [GPT-OSS parser](https://github.com/ollama/ollama/issues/17638) reports corroborate a failure class, not a unique diagnosis for every attempt. Historical open parser changes were not release evidence at the time of the original audit; the supported 0.32.15 upgrade is the actual applied provider change.

Model metadata advertises a 2,048 output limit, but failed request parameters were not captured. Successful inspected outputs exceeded that value and ended normally. An advertised limit is not proof that truncation caused the failures. Never execute guessed/repaired arguments or replay committed effects to improve a benchmark result.

Next work should focus on model adherence, broader conversation/restart and combined resource behavior, then finish the existing consolidated campaign. Provider upgrade, a larger model or simpler tools alone cannot certify the household vision. Failed traces, partial effects and exact cancellation evidence remain retained.
